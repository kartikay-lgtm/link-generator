These are real. Hover to see the states, click to see the behaviour. The “link” below stands in for whatever your page generates.

Why this arrangement. Copy is the filled/primary button because it is the step that has to happen. LinkedIn accepts no pre-filled post text at all, so the caption must be on the clipboard before either platform button is worth pressing. The two post buttons are exact halves of the copy button’s width.

5. JavaScript

Plain browser JS, no dependencies. Change shareText() and the LinkedIn fallback URL; everything else ports as-is.

function el(id) { return document.getElementById(id); }

/* The link rides INSIDE the text rather than as a separate url param — X folds
   a bare url param into the text anyway, and this way the message still reads
   right if a platform keeps only one of the two. */
function shareText() {
  var link = el('link').value.trim();
  var msg  = "I'm hiring on Tal. It's an app where bosses hire directly.";
  return link ? msg + '\n' + link : msg;
}

/* A plain new tab, not a popup: no width/height means the browser opens it
   like a normal clicked link. A fixed-size popup is either ignored on mobile
   or renders too small to use. */
function openShare(url) {
  window.open(url, '_blank', 'noopener,noreferrer');
}

/* ⚠ SYNCHRONOUS on purpose — see §6. */
function copyToClipboard(text) {
  var area = document.createElement('textarea');
  area.value = text;
  area.style.position = 'fixed';
  area.style.opacity = '0';
  document.body.appendChild(area);
  area.focus();
  area.select();
  var ok = false;
  try { ok = document.execCommand('copy'); } catch (e) {}
  document.body.removeChild(area);
  return ok;
}

function flashShareNote(msg) {
  var note = el('share-note');
  note.textContent = msg;
  note.classList.remove('hidden');
  clearTimeout(flashShareNote._t);
  flashShareNote._t = setTimeout(function () { note.classList.add('hidden'); }, 4000);
}

el('copy-content').addEventListener('click', function () {
  var label  = el('copy-content-label');
  var copied = copyToClipboard(shareText());
  if (copied) {
    label.textContent = 'Copied — now paste it in your post';
    clearTimeout(label._t);
    label._t = setTimeout(function () { label.textContent = 'Copy content'; }, 2600);
  } else {
    flashShareNote("couldn't copy automatically — select the text by hand before posting");
  }
});

/* Both post buttons copy again on the way out: whoever pressed Copy content
   first loses nothing, and whoever skipped it still arrives with the caption
   on their clipboard. */
el('share-x').addEventListener('click', function () {
  copyToClipboard(shareText());
  openShare('https://twitter.com/intent/tweet?text=' + encodeURIComponent(shareText()));
});

el('share-linkedin').addEventListener('click', function () {
  var link = el('link').value.trim();
  copyToClipboard(shareText());
  openShare('https://www.linkedin.com/sharing/share-offsite/?url=' +
            encodeURIComponent(link || 'https://tal.club/'));
});

6. The four things that will bite you

① LinkedIn cannot be pre-filled. At all.

The old shareArticle endpoint accepted title and summary; it silently drops them now. The only supported param on /sharing/share-offsite/ is url. The post body is whatever the person types. This is the entire reason the Copy button exists — don’t remove it thinking you can pre-fill instead. X does accept ?text= and works properly.

② Copy must be synchronous, and must happen before window.open

navigator.clipboard.writeText() resolves as a microtask. Fire it and then call window.open() and you race the new tab taking focus — losing that race makes the Clipboard API throw “document is not focused”, silently, since nothing awaits it. The symptom is “the copy button does nothing”. document.execCommand('copy') completes in the same tick, so it wins that race. Deprecated, still universally supported, and the only thing that works here.

③ The hover specificity trap

If your stylesheet has a generic button:hover{background:#0A0A0A} (element + pseudo-class), it outranks .share-btn:hover… no — it ties, and source order decides. In our case it painted the button black without flipping the text, giving black text on a black button. The doubled selector .share-btn.share-btn:hover raises specificity so the inversion always wins. Keep it.

④ Equal halves need flex:1 1 0, not 1 1 auto

“Post on LinkedIn” is a wider label than “Post on X”. With auto it claims more width and the pair looks lopsided. With basis 0 they’re exactly equal. And below 430px the LinkedIn label wraps to two lines while X stays on one — hence white-space:nowrap plus the small type reduction in the media query.

One caveat worth keeping. The X button pre-fills properly, the LinkedIn one cannot. That asymmetry is LinkedIn’s, not a bug to fix — the copy-first flow is the workaround, and the confirmation label is what tells people to paste.
